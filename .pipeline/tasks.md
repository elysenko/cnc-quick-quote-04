# Pipeline Task Decomposition

## Summary
An instant-quote web application for CNC laser cutting. A customer signs up, uploads a DXF drawing, picks a material and quantity, optionally places bend lines on a canvas editor, and receives an itemised price derived from parsed cut length, deterministic grid nesting onto sheets, and an admin-controlled pricing config. A work-bed canvas animates the laser head along the cut path. The customer then checks out through Stripe hosted Checkout, receives an order confirmation page plus a transactional email, and can browse past quotes and orders. Admins configure materials, pricing, machine/upload limits, business branding, shipping methods, and integration credentials from an admin console. **Stack note: the scaffolder provisioned the platform's fixed `enterprise` stack — Angular 19 SPA (`frontend/`) + NestJS/tRPC/Prisma/PostgreSQL (`backend/`). The spec's FastAPI/Python/`ezdxf` implementation is NOT used; all behaviour below is implemented on the scaffolded TypeScript stack (see Open questions).**

**Entities (Prisma models):** `User` (existing), `ColossusAccount` (existing, do not modify), `RefreshToken`, `Material`, `Drawing`, `BendLine`, `Quote`, `ShippingMethod`, `Order`, `PricingConfig`, `MachineConfig`, `BusinessConfig`, `PaymentConfig`, `WebhookEvent`, `SystemSetting`.

**Invariants:** money is integer cents everywhere; dimensions in millimetres, converted to linear feet only inside pricing; `ROUND_HALF_UP`. File budget: 400 lines/file soft, 500 hard. `frontend/package.json` dependencies stay VERBATIM (raw Canvas 2D only, no new frontend packages).

## Open questions
- **Stack conflict (highest impact).** The spec prescribes FastAPI/Python 3.12 with `ezdxf`, but the scaffolder applied the platform's fixed `enterprise` stack (Angular 19 + NestJS/tRPC/Prisma) and `ARCHITECTURE.md` states the FastAPI suggestion is explicitly not used. All tasks above target the scaffolded stack. This invalidates the spec's stated rationale that "Python is mandatory because `ezdxf` is the only mature DXF parser" — DXF parsing must be done in Node (`dxf-parser` or equivalent). Cut-length fidelity for `ARC`/`CIRCLE`/`LWPOLYLINE`/`POLYLINE` must be validated against the fixtures before this is trusted; the spec's `bbox.multi_recursive` and `auditor.has_errors` gates have no direct Node equivalent and need a substitute structural-validity check.
- **Roles.** The spec names roles `admin`/`customer`; the platform contract fixes `enum Role { USER MANAGER ADMIN }` and mints one login per role. Tasks map `customer → USER` and leave `MANAGER` unused. Confirm whether `MANAGER` needs distinct permissions.
- **First-signup-becomes-admin.** The platform seed always creates an `ADMIN` from `COLOSSUS_ACCOUNTS_JSON`, so the spec's bootstrap rule would never fire. Tasks implement "signup gets `ADMIN` only if no `ADMIN` user exists, otherwise `USER`". Confirm this is the intended reconciliation.
- **REST vs tRPC.** The spec lists REST paths (`POST /api/quotes`, etc.); the scaffold's glue is `api_client: trpc`. Tasks map data operations to tRPC procedures and keep REST only for multipart upload, the raw-body Stripe webhook, health, branding, and receipts. Confirm no external consumer depends on the literal REST paths.
- **Seed data.** The spec asks for seeded default materials, shipping methods, and config rows, but the scaffold's build gate flags unguarded sample rows in `seed.js`. Tasks materialise config singleton defaults lazily in the backend and leave materials/shipping empty so admin screens render their empty state. Confirm.
- **Redis is not a provisioned deployment** (`spec_deployments` is `postgresql, minio`) yet the spec depends on it for rate limiting and refresh-token revocation. Tasks add a `redis` service to `docker-compose.yml` and degrade to an in-process limiter plus DB-only revocation when Redis is unconfigured. Confirm whether Redis will be provisioned.
- **Integration env keys are generic** (e.g. `POSTGRESQL_API_KEY`, `MINIO_..._API_KEY`) while the services need multi-field credentials (endpoint, access key, secret key, bucket; connection URL). Tasks treat the provided key as the primary secret and read the remaining fields from conventional env vars — confirm the expected credential shape for `/admin/settings` forms.
- **k8s manifests and separate Dockerfiles** from the spec's Step 1 are omitted: the scaffold ships `backend/Dockerfile`, `frontend/Dockerfile`, `frontend/nginx.conf`, and `colossus.yaml` as the deploy manifest. Confirm no additional `k8s/` directory is required.
- **Receipt format** ("presigned/generated PDF-or-HTML receipt") is unspecified; tasks assume a server-rendered HTML receipt behind `GET /api/receipts/:orderId`.
- **Stripe secret encryption at rest** has no specified key source; tasks assume an app-level `ENCRYPTION_KEY` env var. Confirm.
- **Angular version** — the spec assumes Angular 22 (zoneless, Vitest); the scaffold is Angular 19 with the template's frozen `package.json`. Tests must use the scaffolded runner, not Vitest.
